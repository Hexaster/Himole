0 · Assumptions

  • Adopt to HiMoLE means Build 2 adds the paper method beside the baseline, not by deleting the baseline.
  • The first target remains the EQA setup: train on SQuAD, evaluate ID on SQuAD and OOD on NewsQA.
  • Use Qwen2.5-7B as the practical stand-in already configured in BaselineConfig.
  • Build 2 should prove the routed-expert architecture and tiny smoke path before any long server run.
  • Paper-exact two-stage training is required before claiming a HiMoLE result; random expert init is only for architecture smoke tests.

1 · Architecture target

Keep the frozen base model. Replace the plain single LoRA adapter on FFN projections with grouped LoRA experts and a hierarchical router.

hidden tokens→ sentence avg pool→ group router over N→ token router over N x M→ broadcast + top-k→ LoRA expert delta→ frozen FFN + delta
Key invariant: the baseline path stays runnable. New HiMoLE modules should live behind a separate loader/script so we can compare Base, LoRA, and HiMoLE on the same eval harness.

2 · Approach options

A. Incremental architecture first

Recommended.

Build isolated routed LoRA layers, test shapes and routing math, then wire them into the model and add staged training.

Best balance of correctness, small diffs, and debuggability.

B. Paper-full first

Implement clustering, stage 1, routers, losses, and stage 2 together.

Fast on paper, but high risk: too many possible failure points before the first green test.

C. Notebook-only prototype

Prototype HiMoLE in a notebook without package tests.

Good for learning, but weak as the repo's next build because regressions become hard to catch.

Tick a step only after its verification command passes. Keep changes scoped to the files named in that step.

2 Add explicit HiMoLE configuration

Modify: himole/config.py. Test: tests/test_himole_scaffold.py.

Use the existing HimoleConfig. Do not overload the plain-LoRA rank 80 settings.

  • lora_r=8, lora_alpha=16, lora_dropout=0.05
  • num_kcgs=3, experts_per_kcg=4, top_k=2
  • stage1_lr=3e-4, stage2_lr=3e-5
  • aux_loss_weight, diversity_loss_weight, clustering_encoder
pytest tests/test_himole_scaffold.py::test_himole_config_defaults_match_eqa_build -v

3 Build the routed LoRA layer in isolation

Modify: himole/model/experts.py, himole/model/routing.py, and himole/model/layer.py. Test: tests/test_himole_scaffold.py, then add tests/test_himole_layers.py.

Implement the smallest useful units: LoRA expert deltas, hierarchical router outputs, and a frozen FFN plus N x M trainable expert deltas.

  1. LoRAExpert.forward: low-rank A/B update with scaling alpha / r.
  2. HierarchicalRouter.forward: sentence scores over KCGs and token scores over KCEs.
  3. KnowledgeCompetitionGroup.forward: combine M KCE outputs inside one KCG.
  4. HiMoLEFFNLayer.forward: base FFN output plus weighted expert deltas.
  5. Return routing metadata needed by losses: selected experts, router probabilities, and grouped expert outputs.
Shape to test: sentence scores [B,N] broadcast to [B,T,N,M]; token scores are [B,T,N,M]; final gates keep only top_k experts per token.
pytest tests/test_himole_scaffold.py tests/test_himole_layers.py -v

4 Replace target FFN projections behind a new loader

Write patching code that finds the same FFN target modules as Build 1 and wraps them with HiMoLEFFNLayer. Tiny GPT-2 remains the smoke-test path, so keep its c_fc/c_proj names supported.

  • Freeze all base model parameters.
  • Leave only expert A/B matrices and routers trainable.
  • Print trainable parameter counts, matching the baseline's readability.

5 Add router losses and diagnostics

Modify: himole/train/losses.py. Test: tests/test_himole_losses.py.

Implement the Stage-2 losses before wiring them into training, using tiny tensors that make expected values obvious.

  • L_aux = E * sum(F_i * P_i) for load balancing, where E = N x M.
  • L_diverse: normalize grouped expert outputs and average pairwise cosine similarity across groups.
  • combine_stage2_losses: keep raising until aux_loss_weight and diversity_loss_weight are confirmed.
  • Expose load stats so a training log can show expert imbalance.
pytest tests/test_himole_losses.py -v

Modify: himole/train/stage2.py and scripts/train_himole.py.

Wire the routed layer into a training loop that computes L_task + alpha * L_aux + beta * L_diverse. At this point random expert init is acceptable only as an architecture smoke test.

Add --steps, --samples, and --skip-stage1 flags as part of this step before using the command below.

python scripts/train_himole.py --tiny --steps 5 --samples 8 --skip-stage1
Success: one forward/backward/optimizer path completes, router metadata is present, and the baseline tiny command still works.

7 Add Stage-1 clustering for KCG initialization

Modify: himole/data/clustering.py, himole/train/stage1.py, and scripts/train_himole.py. Optional create: scripts/stage1_init_himole.py.

Embed training examples with the EQA clustering encoder, cluster into N=3 subdomains, then train one KCG per cluster before routing is learned.

  • Cache cluster assignments so reruns do not re-embed unnecessarily.
  • Train each KCG independently on its cluster subset.
  • Copy the KCG initialization into all M=4 experts in that group.

Add the --stage1-only flag as part of this step before using the command below.

5 · Pitfalls to watch

Routing math

  • Broadcast each group score across its M experts before combining with token scores.
  • Apply top_k=2 per token, not per batch.
  • Keep router metadata detached only for logging; losses need gradients through probabilities.

Training discipline

  • Stage 1 is not optional for real HiMoLE results.
  • Keep full validation out of periodic eval; use cfg.max_eval_samples.
  • Move models to CUDA before eval and keep batched generation.

6 · Success criteria

  1. All existing Build-1 tests and tiny smoke runs still pass.
  2. New HiMoLE layer tests prove shape safety, top-k routing, frozen base weights, and trainable expert/router gradients.
  3. Stage-2 tiny smoke training completes with router losses enabled.
  4. Stage-1 initializes distinct KCG expert checkpoints before real Stage-2 training.
  5. The comparison report uses identical prompts, metrics, and eval caps for Base, LoRA, and HiMoLE.
