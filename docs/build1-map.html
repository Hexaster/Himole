1 · The big picture

You take a frozen Llama-2-7B, bolt on tiny trainable LoRA adapters, and fine-tune them on SQuAD so the model answers questions. Then you measure how well it does on SQuAD (in-distribution) and on NewsQA (out-of-distribution). Nothing HiMoLE-specific yet — this is the baseline the real method will be compared against.

4 · Implementation roadmap (the 5 TODOs)

1 Prompt + loss mask

File: himole/data/squad.py · functions build_prompt, format_example

Why it matters: a causal LM is trained to predict the next token. If you score loss on the whole prompt+answer, you also teach it to generate the prompt — you don't want that. You want loss only on the answer. The mask is how.

build_prompt

Fill PROMPT_TEMPLATE with context + question, return the string. It already ends with Answer: (no trailing space).

format_example — the 5 steps

  1. Tokenize prompt alone → prompt_ids (you need its length).
  2. Tokenize prompt + answer → this is your input_ids.
  3. labels = a copy of input_ids, then set the first len(prompt_ids) entries to -100.
  4. attention_mask = all 1s (padding happens later in the collator).
  5. Return {"input_ids","attention_mask","labels"} as lists; respect cutoff_len.
Gotcha A — add_special_tokens=False. Tokenize both strings with no auto BOS/EOS, so prompt_ids is a clean prefix of input_ids and your mask length is exact.
Gotcha B — keep the leading space on answer = " " + .... BPE encodes "Paris" vs " Paris" differently; the space keeps the prefix consistent.
Gotcha C — do NOT shift labels. HuggingFace shifts internally (logits at i vs label i+1). Labels are just a masked copy at the same indices. The test asserts labels[i] == input_ids[i] for unmasked positions.
tokens:  Answer the question ... Answer:   _Paris  <eos>
labels:  -100  -100  -100  ...   -100      _Paris  <eos>
         |<-------- masked (prompt) ------>||<- scored ->|
Verify: pytest tests/test_data_masking.py -v

2 EM + ROUGE-2 metrics

File: himole/eval/metrics.py · 4 functions

Four small functions, each one or two lines once you see it:

  1. normalize_answer(s) — SQuAD style: lowercase → remove punctuation → drop articles (a/an/the) → collapse whitespace. So "The Paris," and "paris" compare equal.
  2. exact_match(pred, gold) — float(normalize_answer(pred) == normalize_answer(gold)).
  3. rouge2(pred, gold) — use the module-level _SCORER: _SCORER.score(gold, pred)["rouge2"].fmeasure.
  4. score_batch(preds, golds) — average EM and ROUGE-2 over all pairs, return {"em":..,"rouge2":..}.
Tip: build the normalizer as 4 tiny steps with re.sub. Mind the order: lowercase before stripping articles.
Verify: pytest tests/test_metrics.py -v

3 Attach LoRA

File: himole/model/baseline_lora.py · function attach_lora

Build a LoraConfig and wrap the frozen model with it. The fields come straight from cfg:

  1. r=cfg.lora_r, lora_alpha=cfg.lora_alpha, lora_dropout=cfg.lora_dropout
  2. target_modules=targets (already computed above — tiny model vs Llama FFN names)
  3. task_type="CAUSAL_LM", bias="none"
  4. peft_model = get_peft_model(model, lora_config)
  5. peft_model.print_trainable_parameters() then return peft_model
What to look for: the printed trainable % should be tiny (about 0.1–1%). That's the whole point of LoRA — you train a sliver, the base stays frozen.
Verify: no unit test; in the notebook run the "Attach LoRA" cell and read the printed trainable parameters.

4 The training step

File: himole/train/loop.py · inside train, the inner loop

The heart of fine-tuning — five lines:

  1. outputs = model(**batch) — HF computes the masked cross-entropy for you (it reads labels).
  2. loss = outputs.loss
  3. loss.backward() — gradients flow into the LoRA params only.
  4. optimizer.step()
  5. optimizer.zero_grad()
Remove the raise line when you implement, and make sure your code runs before the step += 1 / eval block that follows it (which is already written).
Verify: smoke test (below) should now train without raising.

6 · Mini-glossary

LoRA
Freeze base weight W, learn a low-rank update: W' = W + (α/r)·B·A. Only A and B train.
rank r / alpha α
r = size of the bottleneck (capacity). α = scaling. Here r=80, α=160 to match HiMoLE's trainable-param budget.
loss mask (-100)
PyTorch cross-entropy ignores label positions set to -100. We mask the prompt so only answer tokens train.
EM
Exact Match — 1 if the normalized prediction equals the normalized gold answer, else 0.
ROUGE-2
Overlap of 2-grams between prediction and gold; a softer score than EM.
ID / OOD
In-distribution (SQuAD) vs out-of-distribution (NewsQA) — OOD is the robustness HiMoLE targets.
